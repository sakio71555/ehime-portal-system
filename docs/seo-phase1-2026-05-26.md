# SEO改善 第1フェーズ メモ

作成日: 2026-05-26

## 目的

Google Search Console 対策として、インデックスさせるべきページとインデックスさせるべきではないページを整理した。
特に、任意検索結果 URL が検索結果に出る問題を抑えつつ、補助金詳細ページの検索結果表示品質と信頼性表示を強化する。

## 実施した変更

- `/search?keyword=...` ページに `noindex,follow` を出すようにした。
- 静的な `index.html` に残っていた固定 `robots` / description / OGP / Twitter meta を外し、React 側の SEO コンポーネントに統一した。
- WebSite 構造化データから SearchAction を削除した。
- sitemap 生成から `/search` と `/search?keyword=...` 系 URL を除外した。
- 補助金詳細ページの title / meta description を補助金ごとに個別生成するようにした。
- 補助金詳細ページに、申請前に確認すべき公式情報ボックスを追加した。

## SEO上の判断

### `/search?keyword=...` の扱い

検索結果ページは、ユーザーには便利な内部導線だが、検索エンジン向けには重複・低品質ページになりやすい。
そのため、robots.txt ではブロックせず、HTML head に `noindex,follow` を出す方針にした。

robots.txt で `/search` を `Disallow` すると、Google がページ内の `noindex` を確認できない可能性があるため、今回はブロックしない。

### `/search?keyword={search_term_string}` の原因と修正

原因は WebSite 構造化データの SearchAction target に `{search_term_string}` を含む URL テンプレートが出ていたこと。
実リンクとしてクロールされるリスクを避けるため、今回は SearchAction 自体を削除した。

WebSite / BreadcrumbList / GovernmentService など、他の構造化データは維持する。

### sitemap除外ルール

sitemap には canonical として見せたい固定URLだけを含める。
以下は除外する。

- `/search`
- `/search?keyword=...`
- `/search?keyword={search_term_string}`
- 任意検索結果やパラメータ付き検索URL

sitemap に残す主なURLは以下。

- `/`
- `/features`
- `/feature/...`
- `/subsidy/{id}`
- `/columns`
- `/column/{slug}`
- `/expert-articles`
- `/expert-articles/{slug}`
- 固定のSEOランディングページ

## 補助金詳細ページのtitle / description生成ルール

title:

```text
{補助金名}｜{申請期間・補助上限・対象者など存在する項目}｜愛媛の補助金
```

description:

```text
{補助金名}の対象者、補助上限額、申請期間、公募状況、公式情報を整理。{地域名}の事業者・個人向けに要点を確認できます。申請前に必ず公式情報をご確認ください。
```

値がない項目は自然に省略し、`undefined` / `null` / `未確認` などを検索結果向け文言に出さない。

## 補助金詳細ページに追加した信頼性表示

詳細ページ上部に「申請前に確認したい公式情報」ボックスを追加した。

表示項目:

- 公募ステータス
- 申請期間
- 受付開始日
- 受付終了日
- 実施機関
- 対象地域
- 対象者
- 補助上限額
- 補助率
- 公式URL
- 公式情報確認日
- 注意書き: 掲載情報は制度探しの入口であり、申請前に必ず公式ページを確認する

DBに値がない項目は空欄表示を避ける。公式情報確認日は値がない場合 `未確認` として扱う。

### 追加確認: 初期HTMLとJS実行後DOM

2026-05-26 に、ビルド成果物をローカルHTTPサーバーで配信し、初期HTMLとChrome headlessによるJS実行後DOMを確認した。

確認対象:

- `/search?keyword=松山市`
- `/subsidy/1570`

結果:

- `/search?keyword=松山市` の初期HTMLには、SPAの仕様上、動的な `robots` / description / canonical は出ない。
- `/search?keyword=松山市` のJS実行後DOMには `<meta name="robots" content="noindex,follow">` が出る。
- `/search?keyword=松山市` のJS実行後DOMには、検索語に応じた title / description / canonical が出る。
- `/subsidy/1570` の初期HTMLには、SPAの仕様上、動的な title / description / canonical は出ない。
- `/subsidy/1570` のJS実行後DOMには、補助金ごとの個別 title / description / canonical が出る。
- `/subsidy/1570` のJS実行後DOMは `index,follow` のままで、詳細ページに不要な `noindex` は出ない。
- 初期HTMLとJS実行後DOMのどちらにも `{search_term_string}` は出ない。

確認結果の例:

```text
/search?keyword=松山市 JS実行後:
robots: noindex,follow
title: 松山市に関連する補助金・助成金を検索｜愛媛の補助金・助成金ポータル

/subsidy/1570 JS実行後:
robots: index,follow
title: 中小企業者収益力強化補助金｜申請期間・補助上限・対象者｜愛媛の補助金
description: 中小企業者収益力強化補助金の対象者・補助上限額：上限200万円・申請期間：2026年5月29日締切・公募状況：公募中、公式情報を整理。愛媛県内の事業者・個人向けに要点を確認できます。申請前に必ず公式情報をご確認ください。
```

重要な設計メモ:

- 現状のフロントはReact SPAのため、GooglebotがJavaScriptを実行した後に動的metaを確認する設計になっている。
- Search Console の URL検査で `/search?keyword=松山市` の「公開URLをテスト」を行う場合、レンダリング後HTMLで `noindex,follow` が検出される想定。
- ただし、初期HTMLだけを見るクローラーや一部ツールでは動的metaが見えない可能性がある。

### X-Robots-Tag の検討

`/search?keyword=...` の `noindex` をより確実にするには、本番配信側で `/search` にだけHTTPヘッダーを追加する方法が有効。

nginx設定案:

```nginx
location = /search {
    add_header X-Robots-Tag "noindex, follow" always;
    try_files $uri /index.html;
}
```

注意:

- `/`, `/subsidy/...`, `/column/...`, `/features`, `/feature/...` など、インデックスさせたいページには絶対に付けない。
- robots.txt で `/search` を `Disallow` しない方針は維持する。
- 今回はリポジトリ内に本番nginx設定を管理していないため、コード変更としては未実装。必要ならVPS側のnginx設定で別途対応する。

## 未対応事項

- Search Console で古い `/search?keyword=...` URL がインデックス済みの場合、noindex認識まで時間がかかる。
- `published_at` や `official_checked_at` などの確認日系カラムがデータごとに十分埋まっていない可能性がある。
- 補助金詳細の構造化データは今後 `dateModified` やより正確な `additionalProperty` を増やせる。
- lint は既存のバックアップファイルや別作業差分で失敗しているため、別途整理が必要。
- `/search?keyword=...` の `noindex` はJS実行後DOMで出る。必要に応じてVPSのnginxで `X-Robots-Tag: noindex, follow` を追加すると、より確実にGoogleへ伝えられる。
